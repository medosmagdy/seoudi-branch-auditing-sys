# Audit email button access

The recipients administration tab now includes role checkboxes and individual user grants. Roles and explicit users are additive. To grant one person only, clear all roles and select that person. All roles start enabled in the proposed migration, preserving current behavior until an administrator saves a new setting. Admin status still controls access to Administration; an administrator can hide the preparation button from administrators without losing access to this setting.

The UI hides the button when the current active account lacks permission and refreshes permission before creating a file or copying the email. Existing audit visibility, ownership, sharing, manager branch scope and submitted-status checks still apply. The server-side recipient lookup also denies users without the new permission. Because users with audit/report access can use their own email software, this feature controls the app button and recipient lookup; it is not an outbound-mail restriction.

Database proposal: `supabase/proposals/2026-10-30_audit_email_access_REVIEW_ONLY.sql`. It creates one isolated, RLS-enabled settings table and three access-checked functions, and updates the existing recipient lookup to enforce the new gate without replacing its other authorization checks. No existing role assignments, audits, results, scores, or recipient lists are changed. Applied on 2026-10-30 after explicit user approval as migration `audit_email_preparation_access`. Live rollback-only tests verified individual and role grants, hidden admin button without loss of administration, private non-admin context, and denial of settings edits to non-admins. The initial setting remains all three roles and no individual grants; the existing 32 branch recipient lists remain unchanged. RLS is enabled, direct authenticated table reads and anonymous RPC execution are denied. The new administration UI requires the PR to be merged and deployed. The security advisor reports the deliberate RPC-only no-policy table and authenticated SECURITY DEFINER RPC pattern; each function enforces account/admin access internally.
