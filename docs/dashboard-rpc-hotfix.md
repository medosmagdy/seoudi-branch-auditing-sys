# إصلاح استدعاء ملخص Dashboard

الدفعة الثانية تضمنت خطأ في استدعاء Supabase: تخزين `supabase.rpc` في متغير منفصل ثم استدعائه يفقد `this` الخاص بالعميل. أُعيد إنتاج الخطأ باستخدام عميل Supabase الحقيقي، وكانت الرسالة `Cannot read properties of undefined (reading 'rest')` قبل إرسال أي طلب للشبكة.

تم ربط الاستدعاء بالعميل باستخدام `bind(supabase)`. أُضيفت ثلاثة اختبارات تستخدم عميل Supabase الحقيقي مع شبكة وهمية، وتشمل نجاح إرسال الطلب بالفلاتر وإشارة الإلغاء، والحفاظ على رسالة خطأ الخادم، وعدم تسريب حقول إضافية عند عرض التشخيص. مجموع الاختبارات الناجحة 43، بما فيها اختبارات SQL المعزولة السابقة.

أُضيف خيار «عرض تفاصيل الخطأ للدعم» أسفل رسالة فشل الملخص. يعرض رسالة الخطأ ورمزه فقط، دون تسلسل الطلب أو الهيدرز أو التوكنات. إذا بقي الخطأ بعد تطبيق الإصلاح، افتح هذا الخيار وانسخ النص لإكمال التشخيص؛ الصورة العامة وحدها لا تحدد سبب خطأ إضافي في بيئة الإنتاج.

فك ZIP الإصلاح داخل جذر المشروع مع استبدال الملفات المناظرة، ثم ابنِ وانشر التغيير بالطريقة المعتادة. هذا الإصلاح لا يحتاج SQL جديدًا ولا يغير الحسابات أو RLS أو الفحوصات أو التقارير. وظيفة SQL الخاصة بالدفعة الثانية تظل مطلوبة إذا لم تكن قد طُبقت من قبل.

الاختبارات السابقة غطت SQL والحسابات ومحمل التفاصيل، لكنها لم تكشف فقدان ربط عميل Supabase في طلب RPC. اختبار الطلب الجديد يغطي هذا المسار مباشرة. لا يتضمن نجاح الاختبارات تأكيدًا لتطبيق وظيفة SQL أو صحة صلاحيات الحساب في قاعدة الإنتاج.
