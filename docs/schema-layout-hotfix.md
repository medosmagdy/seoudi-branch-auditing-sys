# إصلاح المجزر وتنسيق الفلاتر وتقرير المفتش

تُطبّق هذه الحزمة فوق sqop-phase3-to5-complete السابقة. لا تحتاج SQL جديدًا؛ عمود report_details المطلوب سبق إضافته بملف SQL السابق. لا يوجد نشر تلقائي أو تغيير بيانات في هذه الحزمة.

## إصلاح المجزر

الخطأ سببه أن استعلام التحميل وحقول البيانات الراجعة بعد الحفظ كانا يطلبان slaughtering_evaluation، وهو غير موجود في الجدول المنشور. ملف SQL السابق كان يضيف report_details فقط، لذلك تشغيله لم يعالج طلب العمود القديم.

القراءة والحفظ الآن يستخدمان قائمة حقول واحدة لا تطلب هذا العمود. تقارير النموذج الجديد تقرأ التقييم من report_details.score؛ القديمة من meat_score. لا نضيف عمودًا جديدًا أو نغيّر معادلات أو درجات. التحميل أصبح على صفحات بترتيب ثابت أيضًا. عند وجود خطأ حقيقي آخر يظل ظاهرًا؛ لا يُستبدل بنتيجة فارغة بصمت.

## الفلاتر

المكوّن المشترك المستخدم في أول الصفحة وترتيب الفروع والتفاصيل أصبح شبكة مرنة: عناوين منفصلة فوق الحقول، مسافة 8px بين العنوان والحقل، ومسافات داخلية 16px في مجموعة الفلاتر، وفواصل أفقية 20px. الحقول متساوية الارتفاع 40px وتمتد بعرض المساحة المتاحة. اتجاه قوائم الفرع والبرنامج RTL، والشهر LTR لعرضه بوضوح. على الشاشة الصغيرة تتوزع الحقول على صفوف. حاوية أول الصفحة لها مسافات داخلية إضافية. لم تتغير وظائف الفلاتر أو حساباتها.

## تقرير المفتش

- رأس وفلاتر ثابتة أعلى النافذة، ومحتوى داخلي قابل للتمرير.
- أربع تبويبات واضحة: الملخص، الفحوصات، الفروع، الأقسام.
- الملخص يبدأ بكروت الأعداد، ثم تقييم قبل وبعد، والخصومات داخل جزء قابل للفتح.
- روابط داخل الملخص تنقل مباشرة لتبويب الفحوصات أو الفروع أو الأقسام.
- الفروع تُعرض في كروت لكل برنامج، والأعلى والأقل مميزان بعناوين وألوان وأعداد الزيارات.
- الجداول داخل تبويبها فقط، مع عناوين أوضح، حالات ملونة، وتنقل صفحات موحّد.
- الفلاتر تسري على كل التبويبات، وتعيد صفحات القوائم للبداية عند تغييرها.
- الحسابات وطريقة استبعاد NULL غير N/A من المقارنات كما هي.

## تصدير Excel للمجزر

زر التصدير العام كان مربوطًا برسالة تجريبية فقط. أصبح ينشئ ملف XLSX للتقارير الظاهرة وفق الشهر والنوع والبحث. أضيف نفس الزر بجوار فلاتر التقارير اليومية. تصدير التقرير المنفرد يستخدم نفس مُنشئ الملف لتطابق الحقول.

الملف يتضمن Grand Total (صف لكل تقرير)، وSummary للأعداد ومصدر البيانات والفلاتر، وChecklist وEntered details عند وجود تفاصيل محفوظة. تفاصيل البنود مرتبطة بمعرّف التقرير حتى لا تختلط بين التقارير. لا تُخمن تفاصيل مفقودة للأرشيف. زر التصدير العام معطّل أثناء التحميل أو عند عدم وجود نتائج. في اختبار التصدير تم توليد XLSX وإعادة قراءته للتحقق من الأصفار والملاحظات العربية والأعداد وتفاصيل البنود.

## التطبيق

1. فك الحزمة داخل جذر المشروع مع الحفاظ على المسارات واستبدال الملفات المناظرة، بما فيها src/lib/slaughter-data.ts الجديد.
2. شغّل npm test وnpm run build، وجرّب على Preview، ثم انشر التطبيق.
3. أعد تحميل الصفحة بعد النشر لضمان استخدام الكود الجديد. لا تعِد تشغيل SQL ولا تضف slaughtering_evaluation لحل هذا الخطأ.

## التحقق

نجح 88 اختبارًا، منها اختبار طلب GET وPOST بعميل Supabase الحقيقي وشبكة وهمية ترفض العمود غير الموجود، واختبارات PostgreSQL المعزولة للملخص. اختبارات server rendering تتحقق أن التقرير يبدأ بالملخص ويعرض أربع تبويبات دون إظهار كل الجداول معًا. البناء نجح. فحص TypeScript العام لديه أخطاء سابقة؛ لم تُضف أخطاء جديدة مقارنة بالإصدار السابق.

المراجعة البصرية التفاعلية داخل متصفح لم تُنفذ هنا لعدم توفر Chromium؛ يجب مراجعة Preview على الكمبيوتر والموبايل بالحساب الفعلي، خصوصًا فتح كل تبويب وتغيير الفلاتر وتحميل المجزر وحفظ تقرير جديد. لم تُلمس بيانات الإنتاج أو إجابات NULL القديمة.

للرجوع: استعد ملفات التطبيق السابقة من فرعك. لا يحتاج الرجوع تعديل قاعدة البيانات، لكنه يعيد خطأ العمود في المجزر إذا رجعت للكود السابق.
